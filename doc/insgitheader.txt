*insgitheader.txt* Nvim

Insert file header

============================================================================
                                                           *insgitheader.nvim*

This plugin inserts some information as a comment into the top of the file.

The information added is the file name and path, the name of the git
repository and name and email address of the author.

Name and email address can be set as config option or else are tried to read
from git config or else just print "unknown" and "unknown@example.com" for
author name and email.

The year is the actual year (from system date).

============================================================================
                                                               *InsGitHeader*
Usage:

    `:InsGitHeader`

The command inserts the header if the file has none, and updates it if it
has. No key mapping is set up by the plugin; bind it yourself, for example:
>
    vim.keymap.set('n', '<Leader>ii', '<Cmd>InsGitHeader<CR>')
<
                                                    *insgitheader-placement*
Placement:

If the file starts with a line that has to stay on top, the header is put
below it, separated by a blank line, so the file keeps working. Recognised
are `#!` , `<?xml` , `<?php` , an encoding declaration such as
`# -*- coding: utf-8 -*-` and `@charset` . At most the first two lines are
treated this way. Blank lines that are already there are reused instead of
doubled.
>
    #!/usr/bin/env bash

    # file: /home/jd/bin/backup.sh
    # git: /home/jd/dotfiles
    # author: John Doe <jd@example.com> 2024

    set -euo pipefail
<
                                                       *insgitheader-update*
Update:

An existing header is recognised by three consecutive `file:` , `git:` and
`author:` lines right below the prologue, starting with the comment
character of the current 'commentstring'. Those three lines are replaced;
everything around them stays untouched.

The year of the old header is carried over and extended into a range, for
example `2019` becomes `2019-2024` . If the old header names a different
author, that author is appended to a chain, oldest first:
>
    -- author: John Doe <jd@example.com> 2019-2024 (orig. Jane Roe <jr@example.com>)
<
Note: if 'commentstring' has changed since the header was written, the old
header is not recognised and a second one is inserted above it.

If an existing header sits above a shebang, it is updated where it is and a
warning is issued, since the shebang has no effect in that position.

                                                      *insgitheader-chezmoi*
chezmoi:

Files managed by chezmoi (https://www.chezmoi.io/) are marked in the `git:`
line. This covers both the target file and its source file in the chezmoi
source directory:
>
    # file: /home/jd/.bashrc
    # git: /home/jd/.local/share/chezmoi (managed by chezmoi)
    # author: John Doe <jd@example.com> 2024
<
For a source file the `file:` line shows the target path, so the header is
identical in source and target and `chezmoi apply` produces no diff. Files
inside the source directory that are not chezmoi entries, such as README.md,
keep their real path.

chezmoi is optional. If the executable is not found, nothing is marked and no
error is shown. The plugin keeps trying, so installing chezmoi mid-session
starts working without restarting Neovim.

                                                *b:insgitheader_chezmoi*
The result of the chezmoi lookup is remembered per buffer in the buffer
variable `b:insgitheader_chezmoi` , so repeated calls in the same buffer cost
no extra processes. Inspect it with:
>
    :echo b:insgitheader_chezmoi
<
It holds the path it was determined for, whether the file is managed, the
chezmoi repository and, for a source file, the target path.

The entry is dropped, and the lookup runs again, when

    - the buffer is written (|BufWritePost|), which also picks up a source
      file that did not exist yet the first time round, and
    - the buffer changes its name (|BufFilePost|), as with |:saveas| or
      |:file| .

A `chezmoi add` done outside Neovim is therefore picked up the next time the
buffer is written or renamed, not immediately.

                                                        *insgitheader.setup()*
Configuration:
>
    require('insgitheader').setup {
            name = 'John Doe',
            email = 'jd@example.com',
            path = 'full'
    }
<
Options:

    `name`  Set author name. Optional. If omitted, |InsGitHeader| will call
          `git config user.name` to get the name, else it will use
          `unknown` as author name.

    `email`  Set authors email address. Optional. If omitted, |InsGitHeader|
           will call `git config user.email` to get the address, else it will
           use `unknown@example.com` as authors email address.

    `path`  What the `file:` line shows. Optional, one of:

           `full`      path and file name (default)
           `basename`  file name only

          Any other value is ignored with a warning. For a chezmoi source
          file the name is taken from the target path, so source and target
          still produce the same line. Example with `basename` :
>
    -- file: init.lua
    -- git: /home/jd/foo.git
    -- author: John Doe <jd@example.com> 2024
<

How it looks:
>
    -- file: /home/jd/foo.git/bar.lua
    -- git: /home/jd/foo.git
    -- author: John Doe <jd@example.com> 2024
<
See also |insgitheader-placement| , |insgitheader-update| and
|insgitheader-chezmoi| .
